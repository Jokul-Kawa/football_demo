# 中足联职业联赛智能运营平台项目计划书

## 1. 项目定位

本项目面向中国足球职业联赛联合会，暂定名为“中足联职业联赛智能运营平台”。平台不再面向普通球迷，也不再以世界杯、英超资讯、抽卡或赛果预测为目标，而是服务中超、中甲、中乙及职业俱乐部梯队赛事的组织运营、准入审查、赛事管理、球员注册、场馆管理、纪律案件、商务权益交付和数据决策。

产品形态为：

- 移动端工作 App：服务赛事监督、场馆负责人、俱乐部工作人员和现场执行人员。
- Web 管理后台：服务中足联各业务部门、地方会员协会和俱乐部管理人员。
- 数据中台：沉淀联赛、俱乐部、球员、场馆、比赛、准入、纪律、商务和风险数据。
- AI 工作助手：辅助材料审查、风险提示、报告生成、会议纪要和文书草稿。

项目目标不是“做一个好看的 App”，而是提出一组能让中足联提升工作效率、治理透明度和联赛运营能力的数字化突破点，用于争取项目预算。

公开依据：

- 中足联官网已公开设置赛程、俱乐部、球员、数据、商务、纪律处罚、官方文件等栏目：https://www.cfl-china.cn/zh/index.html
- 央视新闻报道中足联负责职业联赛发展规划、俱乐部准入、球员注册转会、纪律处罚等工作，裁判选派评议处罚仍由中国足协负责：https://sports.cctv.cn/2025/01/23/ARTIynN4THiKxt3qrlwc7paq250123.shtml
- 中足联已发布 2026 赛季职业联赛准入相关公告：https://www.cfl-china.cn/zh/content/announcements/bRVz.html

## 2. 核心痛点

### 2.1 准入审查材料多、链条长

职业俱乐部准入涉及主体资质、财务约定、债务清偿、工资支付、梯队建设、场馆条件、纪律记录等材料。传统方式容易出现材料版本混乱、补正往返耗时、人工查缺压力大、公示投诉难追踪等问题。

### 2.2 比赛日协同依赖人工沟通

比赛日前后涉及竞赛、安保、场馆、草坪、灯光、转播、媒体、商务、票务、客队接待、球迷组织等多个角色。微信群、电话和表格难以沉淀过程数据，也难以及时形成赛后复盘。

### 2.3 场馆准入和整改缺少移动化闭环

草坪、安全通道、灯光、转播机位、媒体区、医疗通道和观众动线等检查项需要现场取证、整改跟踪和复检。缺少统一工具时，证据留存和整改责任容易分散。

### 2.4 球员注册转会材料审核压力大

球员注册和转会涉及身份、合同、报名名额、外援名额、资格限制、窗口期和纪律处罚等规则。人工审核容易重复劳动，且难以快速发现材料缺失和规则冲突。

### 2.5 纪律案件与处罚文书需要标准化

纪律案件涉及证据收集、事实认定、规则引用、审批流转和文书生成。平台需要提高流程可追溯性，减少重复写作，同时保留人工判断和正式审批权。

### 2.6 领导决策缺少实时运营驾驶舱

联赛运行质量、俱乐部经营健康、重点比赛风险、商务权益交付、纪律案件进展和场馆整改状态需要统一看板，而不是散落在多个部门文件中。

## 3. 创新提案池

### 3.1 AI 俱乐部准入审查助手

自动读取准入材料清单，识别缺失项、过期项、冲突项和高风险项，生成“准入摘要”“补正建议”“债务清偿风险提示”和“公示投诉处理摘要”。

业务价值：减少人工查缺时间，提高准入审核一致性。

### 3.2 职业联赛比赛日移动指挥舱

把比赛日任务拆成赛前、赛中、赛后清单，现场人员通过移动端完成签到、巡检、事件上报、照片取证和整改确认。领导端实时查看重点比赛风险。

业务价值：把比赛执行从“靠群聊协调”升级为“可追踪、可复盘、可考核”的流程。

### 3.3 场馆准入与巡检闭环

建立场馆档案、准入标准、巡检清单、整改任务、复检证据和评分体系。支持草坪、灯光、安保、转播、医疗、媒体区等维度。

业务价值：减少场馆问题在比赛日前集中暴露，提高联赛基础保障水平。

### 3.4 球员注册与转会智能校验

对合同、身份、报名名额、外援名额、窗口期、纪律限制和材料完整性进行自动校验，并把异常项推送给俱乐部和审核人员。

业务价值：降低注册转会审核压力，减少违规报名风险。

### 3.5 纪律案件文书助手

针对比赛监督报告、证据材料和历史处理记录，生成事实摘要、证据清单、规则引用建议和处罚文书草稿。最终决定仍由人工审核。

业务价值：提升文书质量和流转效率，强化审计留痕。

### 3.6 俱乐部经营健康雷达

围绕准入材料、债务投诉、纪律处罚、商务履约、青训梯队、赛风赛纪和舆情风险形成俱乐部健康评分。

业务价值：从事后处置转向提前预警，帮助中足联掌握俱乐部运行风险。

### 3.7 商务权益交付管理

管理赞助权益、场边广告、转播露出、媒体活动、俱乐部执行反馈和交付证明，形成可核验的商务履约台账。

业务价值：提升商业合作交付确定性，增强联赛商业价值。

### 3.8 青少年精英联赛与梯队人才地图

沉淀 U21、梯队球员、比赛表现、报名资格和俱乐部青训建设数据，形成职业联赛后备人才地图。

业务价值：把职业联赛运营和青训评价连接起来，支撑长期发展规划。

### 3.9 联赛年度报告自动生成

自动汇总赛程、观众、纪律、场馆、商务、俱乐部、球员注册、风险和整改数据，生成年度运营报告初稿。

业务价值：减少年终汇总工作量，为管理层和合作方提供结构化成果。

## 4. 一期 MVP

一期不做完整大而全系统，建议聚焦三个闭环，形成能演示、能落地、能体现预算价值的版本。

### 4.1 准入审查闭环

功能范围：

- 俱乐部提交准入材料。
- 地方会员协会初审。
- 中足联复核。
- 债务清偿状态管理。
- 公示投诉记录。
- 退回补正和最终审核状态。
- AI 自动生成准入摘要、缺失项和风险提示。

核心对象：

- `ClubAdmission`
- `DebtClearanceCase`
- `WorkflowTask`
- `RiskAlert`
- `AIReport`
- `AuditLog`

### 4.2 比赛日运营闭环

功能范围：

- 比赛日任务清单。
- 安保、转播、媒体、场馆、商务任务跟踪。
- 现场事件上报。
- 风险等级自动升级。
- 赛后复盘报告。

核心对象：

- `MatchOperation`
- `WorkflowTask`
- `RiskAlert`
- `AIReport`
- `AuditLog`

### 4.3 场馆巡检闭环

功能范围：

- 场馆档案。
- 草坪、灯光、安保、转播、医疗、媒体区巡检清单。
- 图片/视频证据占位。
- 整改任务。
- 复检和评分。
- AI 生成整改建议。

核心对象：

- `VenueInspection`
- `WorkflowTask`
- `RiskAlert`
- `AIReport`
- `AuditLog`

## 5. 系统架构

### 5.1 客户端

- 移动端工作 App：现场任务、巡检、事件上报、待办处理、AI 摘要查看。
- Web 管理后台：业务配置、流程审批、材料审核、统计看板、报告导出。

### 5.2 后端

- REST API 提供业务接口。
- PostgreSQL 存储联赛、俱乐部、球员、场馆、准入、比赛日、纪律和审计数据。
- Redis 缓存运营驾驶舱、重点比赛风险和待办统计。
- 对象存储保存材料、图片、视频、报告附件。
- AI 服务以内部助手形态接入，不直接作出正式审批或处罚决定。

### 5.3 权限

角色建议：

- 中足联管理员。
- 准入审核员。
- 竞赛运营人员。
- 场馆巡检员。
- 俱乐部经办人。
- 地方会员协会审核员。
- 赛事监督。
- 商务执行人员。
- 领导只读账号。

权限原则：

- 敏感材料默认最小权限可见。
- 所有审批、退回、补正、文书生成和状态变更必须进入审计日志。
- AI 输出必须人工确认后才能进入正式流程。

## 6. API 与数据模型

当前 MVP API：

- `GET /dashboard/operations`：联赛运营驾驶舱。
- `GET /leagues`：联赛列表。
- `GET /clubs`：俱乐部列表。
- `GET/POST /club-admissions`：准入材料与审核状态。
- `POST /club-admissions/{id}/review`：准入状态流转。
- `GET/POST /match-operations`：比赛日运营任务。
- `POST /match-operations/{id}/incidents`：现场事件上报。
- `GET/POST /venue-inspections`：场馆巡检记录。
- `GET/POST /player-registrations`：球员注册/转会材料，需管理员权限。
- `GET/POST /discipline-cases`：纪律案件，需管理员权限。
- `POST /ai/reports/generate`：AI 报告生成。
- `GET /ai/reports`：AI 报告列表。
- `GET /audit-logs`：审计日志，需管理员权限。

核心数据模型：

- `League`
- `Season`
- `Club`
- `ClubAdmission`
- `DebtClearanceCase`
- `PlayerRegistration`
- `TransferCase`
- `MatchOperation`
- `VenueInspection`
- `DisciplineCase`
- `CommercialAsset`
- `WorkflowTask`
- `RiskAlert`
- `AIReport`
- `AuditLog`

## 7. 分阶段实施

### 阶段一：预算演示版

目标：形成可演示的业务闭环，用于汇报和争取预算。

交付：

- 运营驾驶舱。
- 准入审查流程。
- 比赛日运营任务。
- 场馆巡检记录。
- AI 报告生成。
- 审计日志。

### 阶段二：试点运行版

目标：选择一个联赛或若干俱乐部进行真实试点。

交付：

- 真实账号和权限。
- 文件上传。
- 状态流转。
- 任务提醒。
- 报告导出。
- 试点数据看板。

### 阶段三：全国职业联赛推广版

目标：覆盖中超、中甲、中乙及职业俱乐部梯队赛事。

交付：

- 统一数据中台。
- 多联赛管理。
- 俱乐部健康雷达。
- 商务权益交付。
- 纪律案件文书助手。
- 年度报告自动生成。

## 8. 验收标准

- 准入流程能完成提交、初审、复核、退回补正、审核通过和审计留痕。
- 比赛日流程能完成任务分派、现场事件上报、风险升级和赛后复盘。
- 场馆巡检能完成清单检查、证据留存、整改状态和评分。
- 球员注册与纪律案件接口具备管理员权限保护。
- AI 报告能生成摘要、风险提示、输入数据版本、生成时间和人工审核状态。
- 审计日志记录操作者、角色、动作、对象、时间和说明。
- 文档明确本系统不替代人工审批、纪律决定和中国足协裁判管理职责。

## 9. 关键风险

- 职责边界：裁判选派、评议和处罚按公开资料仍由中国足协负责，本系统只做比赛日协同和数据接口预留。
- 数据敏感：球员合同、薪酬债务、俱乐部经营材料和纪律案件需要严格权限和审计。
- AI 风险：AI 只能做辅助摘要和风险提示，不能自动批准准入、认定处罚或替代正式文书。
- 组织协同：中足联、地方会员协会、俱乐部和场馆角色多，必须先用试点验证流程。
- 预算表达：提案必须突出效率提升、风险前置、治理透明和数据沉淀，而不是单纯讲技术。
